# Дизайн: выбор технологии взамен shell-логики

**Дата:** 2026-07-15
**Статус:** утверждён (brainstorming), готов к написанию плана
**Автор:** Claude (Opus 4.8) + Stsiapan
**Связано:** STS-74 (выбор технологии, эта задача), реализация вынесена в отдельную задачу

## Проблема

Вся логика деплоя написана на bash: `setup.sh` плюс 10 модулей `lib/*.sh`, около 600 строк,
и около 800 строк тестов в `skills/tools/`. Bash даёт переносимость и отсутствие зависимостей,
но код тяжело читать и поддерживать, а проект пишется через ИИ и растёт.

Проблема не абстрактная. Конкретные её проявления в текущем коде:

1. **Stringly-typed булевы через позиционные аргументы.** `setup.sh:56` вызывает
   `deps_apply "$c7_dep" "$pw_dep" "$az_dep" "$ado_dep" "$dn_dep" "$cr_dep"`: шесть подряд
   идущих булевых строк. Перепутанный порядок не ловится ничем, ни компилятором, ни рантаймом.
   Та же схема в `settings_apply` и `skills_apply` (`profiles.sh:8-9,20-21`).
2. **Язык не тянет собственную предметную область.** Bash не умеет JSON, поэтому Python уже
   стал вторым языком: `lib/py/config_io.py` (64 строки), `lib/py/jsonmerge.py` (50),
   `claude/mcp/build_servers.py` (46), плюс inline `python3 -c` в `setup.sh:34,61,75`.
   Граница sh/py проходит через subprocess: каждое чтение ключа конфига (`config.sh:9-13`) это
   отдельный запуск интерпретатора.
3. **Интерпретатор на горячем пути.** `statusline.sh:5` на каждый рендер статусной строки
   поднимает `bash` + `cat` + `python3`, чтобы распарсить JSON со stdin. Это около 25-40 мс на
   рендер ради разбора одного маленького объекта.

## Цель

Один язык вместо связки bash + Python, с типами и нормальными тестами, при этом без потери
главного свойства текущего решения: машина не должна ничего доустанавливать ради инструмента.

## Ограничения (проверено на этом репозитории)

- **Репозиторий сегодня является рантайм-артефактом, а не разовым bootstrap.** `skills.sh:31`
  делает `ln -sfnT "$root/claude/skills/dotnet-router"` из `~/.claude-super/skills/` внутрь
  клона. Проверено на машине: симлинк указывает в `~/.local/share/claudefiles`, то есть во
  второй клон репозитория (у него свой `.git`).
- **Часть артефактов зашить в бинарь невозможно.** `skills.sh:22-24` клонирует сторонний
  `dotnet/skills` в рантайме, `skills.sh:27` генерирует каталог с абсолютными путями этой
  машины. Это данные, зависящие от машины и от стороннего репо, они обязаны оставаться
  рантайм-артефактами.
- **Свои ассеты малы и статичны:** 252K (`claude/settings/*.template.json`,
  `claude/skills/*/SKILL.md`, `claude/sounds/ready.wav`). Их зашить можно.
- **Мерж JSON принципиально бесхемный.** `invariants.md:9` требует, чтобы при миграции
  super в vanilla пользовательский контент и неизвестные ключи сохранялись. Значит инструмент
  обязан читать и переписывать чужой `settings.json`, не зная его схемы.
- **`git` останется зависимостью в любом случае** (клон `dotnet/skills`, `skills.sh:24`).
- **Репозиторий публичный** (`github.com/stpntkhnv/claudefiles`), значит скачивание релиза
  идёт обычным `curl` без токена.
- **Окружение машины на момент решения:** python 3.14.6, go присутствует, dotnet SDK 10.0.109,
  rust отсутствует.

## Не-цели (осознанный YAGNI)

- Кроссплатформенность за пределы Linux. Инструмент завязан на pacman (`deps.sh:6-18`),
  расширение платформ это отдельное решение.
- Кросс-компиляция под несколько архитектур. Одна цель: linux/amd64.
- Переписывание `skills/dotnet-skills/**` (сторонний репозиторий) и `legacy/**`.
- Смена поведения. Миграция обязана быть поведенчески нейтральной.

## Решение

**Go, только стандартная библиотека, один статический бинарь, доставка через GitHub Releases.**

Обоснование по пунктам, каждый привязан к факту выше:

1. **Только компилируемый язык чинит горячий путь.** `statusline.sh` поднимает интерпретатор
   на каждый рендер. Бинарь отвечает за ~2 мс вместо ~30 мс. Ни Python, ни bash этого не
   исправляют в принципе.
2. **Самодостаточный артефакт.** Репо публичное, значит `curl` бинаря с Releases без auth.
   После этого единственная рантайм-зависимость это `git`, который нужен и так.
3. **Типы снимают текущий класс багов.** Шесть позиционных булевых строк (`setup.sh:56`)
   становятся структурой с именованными полями, ошибка ловится на компиляции.
4. **Ноль сторонних зависимостей.** `os/exec`, `encoding/json`, `flag` покрывают всю
   предметную область. Дух «нет зависимостей» сохраняется буквально, `go.sum` остаётся пустым.
5. **Бесхемный мерж ложится на язык естественно.** `map[string]any` из `encoding/json`
   позволяет мержить чужой JSON, сохраняя неизвестные ключи, без описания схемы.
6. **Прецедент в том же домене.** chezmoi, менеджер dotfiles, написан на Go.

### Рассмотренные и отклонённые варианты

**Python.** Честно более дешёвый путь, и это зафиксировано осознанно. Уже обязателен
(`setup.sh:7` делает `require_cmd python3`), уже 160 строк в репозитории, ноль шага сборки,
наименьшая церемония для subprocess-клея, миграция могла бы идти инкрементально по модулю.
Отклонён по двум причинам: не даёт самодостаточного артефакта (`zipapp` из stdlib даёт один
`.pyz`, но интерпретатор всё равно нужен) и не чинит горячий путь `statusline.sh`. Цена
решения: новый язык и шаг сборки. Принята сознательно.

**C#.** Родной язык автора, что весомо для читаемости, но здесь худший bootstrap:

- Циклическая зависимость: инструмент сам ставит `dotnet-sdk` по флагу (`deps.sh:76`), значит
  SDK не может быть его предусловием.
- Установленный SDK 10.0.109 это feature band 10.0.100, а `#:include`/`#:exclude` требуют
  10.0.300+. То есть на текущем SDK вся логика жила бы в одном файле.
- File-based apps включают native AOT по умолчанию, под AOT рефлексивный `JsonSerializer`
  падает и требует source-gen контекстов. Для бесхемного мержа (`invariants.md:9`) source-gen
  неприменим по определению: типов нет.
- Скилл `csharp-scripts` в разделе «When Not to Use» исключает ровно этот кейс дважды:
  «shell/Python/PowerShell-style automation» и «large enough that project structure, build
  customization, tests, or publish configuration should live in a `.csproj`».

Вариант «полноценный `.csproj` + AOT-бинарь» снимает часть возражений, но требует SDK и
линковочных зависимостей (clang, zlib) на машине сборки ради результата, который Go даёт
меньшей ценой.

**Rust.** Сильные стороны не применимы: нет CPU-bound участков, нет конкурентности, нет FFI,
процесс живёт секунды и ждёт `pacman`. Слабые применимы: для бесхемного мержа `serde`
бесполезен (жизнь в `serde_json::Value` теряет главный козырь), CLI на практике тянет
`serde`/`clap`/`anyhow` против stdlib-only у Go, компиляция десятки секунд против единиц,
borrow checker это недели для C#-разработчика ради 600 строк клея. Единственный кандидат,
которого нет на машине.

## Целевая архитектура

Главный архитектурный сдвиг: **репозиторий перестаёт быть рантайм-артефактом**. Бинарь владеет
data-каталогом `~/.local/share/claudefiles`, симлинк `dotnet-router` указывает туда, а не в
клон репо. Репозиторий нужен только для разработки.

```
cmd/claudefiles/          подкоманды: setup, statusline, detect-dotnet, verify
internal/
  config/                 заменяет config.sh + lib/py/config_io.py
  settings/               заменяет settings.sh + lib/py/jsonmerge.py
  mcp/                    заменяет mcp.sh + claude/mcp/build_servers.py
  skills/  plugins/  claudemd/  deps/  profiles/
  assets/                 go:embed своих 252K
setup.sh                  остаётся, ~15 строк: curl бинаря и запуск, без логики
```

Один бинарь заменяет три вида скриптов: bootstrap (`setup.sh` + `lib/*.sh`), рантайм-хуки
(`statusline.sh`, `detect-dotnet.sh`) и Python-помощники.

Границы модулей сохраняются от текущих: модули-appliers идемпотентны и владеют своим
артефактом (`architecture.md:126`). Изоляция профилей, сегодня реализованная субшеллом с
экспортом env (`profiles.sh:73`), в Go становится явным параметром, а не глобальным состоянием.

## Миграция

Двухтактно, со страховкой существующими тестами.

Тест-сьют разделён по типу, это проверено:

- **Чёрный ящик, переживает переписывание без изменений:** `test-setup-idempotent.sh`,
  `test-multiprofile.sh` (запускают `setup.sh` и проверяют файлы в песочнице HOME),
  `test-statusline.sh`, `test-secrets-not-tracked.sh`.
- **Юнит, умирает вместе с bash-модулями:** 8 тестов, делающих `source lib/*.sh`
  (`test-config.sh`, `test-settings.sh`, `test-skills.sh`, `test-plugins.sh`,
  `test-profiles.sh`, `test-mcp.sh`, `test-claudemd.sh`, `test-head-compare.sh`).

Такт 1: чёрный ящик натравливается на Go-бинарь без правок. Он пиннит самые ценные инварианты
(идемпотентность и полноту миграции super в vanilla, `invariants.md:5,9`) и служит критерием
катовера.

Такт 2: модули переносятся по одному, 8 юнит-тестов портируются в Go table-тесты. Катовер,
когда чёрный ящик зелёный на Go-бинаре.

## Тестирование

- Go table-тесты вместо 8 юнит-тестов на bash, песочница через `t.TempDir()`.
- Внешние команды (`pacman`, `claude`, `git`) за интерфейсом, чтобы тесты не трогали систему.
  Сегодня это решается подменой PATH через `faketools.bash` (`skills/tools/lib/faketools.bash`).
- Чёрный ящик остаётся на bash как acceptance-слой, менять его не требуется.
- Инварианты из `invariants.md` это чеклист приёмки, каждый пункт обязан остаться зелёным.

## Риски

- **Регресс поведения при переписывании 600 строк.** Митигация: чёрный ящик как критерий
  катовера, поведенческая нейтральность как явное требование.
- **Смена владельца data-каталога.** Существующий симлинк указывает в клон репо. Нужен
  одноразовый переезд на `~/.local/share/claudefiles`, иначе `dotnet-router` отвалится.
- **Новый язык для автора.** Митигация: только stdlib, без фреймворков; объём (600 строк
  прямолинейного клея) посилен для входа.
- **CI-релизы как новая машинерия.** Митигация: одна цель linux/amd64, workflow на сборку по
  тегу и загрузку ассета.
